Hyper CDC Orchestrator:
OLake Analytics-first Control Plane

Analytics-first CDC replicates committed database changes directly into governed Apache Iceberg tables. Hyper CDC remains the operator-facing control plane. OLake performs high-throughput snapshot, incremental, and CDC loads through Temporal-coordinated driver containers. Kafka Connect is not on this path.

System Overview
Hyper CDC
Orchestrator
OLake Analytics-first
1
Operators / Agents
Users reach the platform through Kafbat WebUI or an MCP agent. OLake credentials never leave the server.
2
DNS / Ingress
DNS resolves to the global ingress endpoint and terminates the public hostname for the control plane.
3
Reverse Proxy
Provides TLS termination and high-availability load balancing across control-plane replicas.
4
Control Plane
Nuxt WebUI serves the console, cdc-orchestrator owns /cdc/olake policy, and mcp-cdc exposes agent tools.
5
OLake Runtime
OLake API, Temporal, and the worker launch ephemeral Go driver containers. No Kafka or Debezium on this path.
6
Iceberg Lake
S3/MinIO stores Parquet files. The Iceberg catalog registers snapshots, manifests, and schema evolution.
7
Databases
Sources are read only through OLake drivers. One reader per host/port/database is enforced.
8
Observability
Prometheus, dashboards, alerts, logs, traces, and Temporal UI cover jobs, workers, and lake writes.
